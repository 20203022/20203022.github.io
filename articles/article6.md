## 为什么 Prompt 质量决定产出质量？

Vibe Coding 的核心是「用自然语言驱动代码生成」。Prompt 是你的输入，输入质量直接决定了输出质量。同样的 AI 工具，好的 Prompt 和差的 Prompt，效率差距可达 10 倍。

## 一个好的 Prompt 的结构

### 1. 角色设定（可选）
告诉 AI 它当下的角色，帮助它进入正确的上下文。

### 2. 任务描述（必须）
清晰地说明要做什么。

### 3. 技术约束（重要）
指定技术栈、版本、规范要求。

### 4. 上下文信息（关键）
提供相关的现有代码路径、数据库表结构等。

### 5. 输出格式（明确期望）
告诉 AI 你期望它输出什么。

## 实战对比

### 差的 Prompt
"帮我做一个用户管理功能"
AI 不知道技术栈、不知道数据结构、不知道范围，只能猜测你的意图。

### 好的 Prompt
"基于现有的 User Entity (com.example.model.User，字段有 id/username/email/role)，在 Spring Boot 3.2 项目中创建用户管理 API：1) GET /api/admin/users 分页列表 2) PUT /api/admin/users/{id}/toggle 启用/禁用 3) DELETE /api/admin/users/{id} 删除。要求使用 JPA Repository、添加 @PreAuthorize 权限控制。"

## Prompt 模板库

### 创建新功能
```
在 [项目名称] 中实现 [功能名称]：
1. [具体需求 1]
2. [具体需求 2]
技术栈：[技术栈]
相关文件：[现有文件路径]
```

### Bug 修复
```
[文件路径:行号] 出现了 [错误现象]。
预期行为：[预期] 实际行为：[实际]
请分析原因并修复。
```

### 代码重构
```
重命名 [文件路径] 中的 [方法/变量名] 为 [新名称]。
同时更新所有引用该名称的文件。
```

## 进阶技巧

### 1. 渐进式细化
第一轮给出大方向，第二轮细化细节，不要试图一次完美。

### 2. 使用示例
给 AI 看一个你期望的输出示例，比语言描述更有效。

### 3. 主动设限
告诉 AI **不要做什么**和告诉它要做什么同样重要。

### 4. 使用 CLAUDE.md
项目级的 CLAUDE.md 是「隐式的 Prompt」，每次对话都自动加载。

## 总结

写出好的 Prompt 是一门需要练习的技能。核心原则是：**把 AI 当成一个聪明但对你项目一无所知的新同事，你需要给它足够的上下文才能高效协作。**

好的结果 = 清晰的需求 + 充分的上下文 + 具体的约束 + 明确的输出格式
